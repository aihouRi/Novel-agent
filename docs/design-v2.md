# Novel Agent V2 设计书

更新时间：2026-05-23

## 1. 文档目的
本设计书用于定义 V2 的目标、范围与约束，作为 V1 之后的迭代基线。

## 2. V2 目标
在 V1 可用基线之上，重点提升：
- 生成质量：降低跑偏、遗忘设定、风格不稳问题。
- 检索能力：让 AI 基于可追溯的上下文生成，而不是仅靠最近章节。
- 发布可用性：强化数据安全、导出与恢复能力，支持更稳定的长期创作。

## 3. 承接 V1 已完成基线（不在 V2 重复计入）
以下能力已在 V1 完成，不再作为 V2 新目标重复计算：
- 用户认证与数据隔离（Auth + user_id 权限约束）。
- 小说/分卷/章节/角色/设定卡 CRUD。
- AI 章节生成（OpenAI/Gemini）与用户级 AI 设置。
- 章节写作页关键工具（历史回填、模板、快速修订、局部重写、快照）。
- Markdown 导出（范围/状态/内容项）。
- 前端结构重构与懒加载/分包性能优化。

## 4. V2 范围（新增）
- RAG 最小闭环：
  - 章节/角色/设定的结构化检索与上下文召回。
  - 生成前可配置参考来源与召回策略。
- AI 工作流升级：
  - 从单次生成升级为“计划 -> 生成 -> 自检 -> 改写”闭环。
  - 一致性检查（设定冲突、时间线、角色状态）。
- 发布可用性增强：
  - 数据安全（备份、恢复、关键操作保护）。
  - 导出能力增强（模板化、可选结构化导出）。
- 定稿后结构化信息沉淀：
  - 仅针对“定稿章节”做人物/物品/设定等实体抽取。
  - 抽取结果先结构化展示，再由用户确认入库。
  - 严格字段边界：只写入可从正文明确确认的字段，不自动改“人物权重”等策略字段。

## 5. V2 当前进展
- 待开始（本文件为 V2 初始化文档骨架）。

## 6. V2 非目标（初稿）
- 多 Agent 编排平台化。
- 商业化协作后台与权限系统细粒度扩展。
- 与外部云盘/第三方内容平台的深度集成。

## 7. 约束与原则
- 延续既有技术栈（Go + Echo、React + TypeScript + MUI）。
- 采用小步迭代：每阶段单独交付、单独验证、单独记录。
- 不破坏 V1 现有可用链路。
- 高风险改动先补文档与回滚路径，再上线代码。
- 迭代期间持续处理新增 bug，不堆积到阶段末。
- 迭代期间可持续进行代码优化与性能优化（在不破坏业务闭环前提下）。
- 迭代期间可持续进行数据库优化（索引、查询、迁移策略），并保持可回滚。

## 8. 验收标准（V2 总体）
- 质量：AI 生成一致性与可控性可见提升。
- 稳定：关键流程有明确失败兜底与恢复路径。
- 可维护：文档、测试、结构同步更新。
- 数据可信：AI 自动沉淀仅落地“可明确确认事实”，不擅自覆盖策略字段。
