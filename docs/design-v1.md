# Novel Agent V1 设计书

更新时间：2026-05-20

## 1. 文档目的
本设计书用于定义 V1 的目标、范围与约束，作为 MVP 之后的迭代基线。

## 2. V1 目标
在不偏离 MVP 核心方向的前提下，提升三个方面：
- 稳定性：减少回归与线上故障概率。
- 可维护性：降低前后端后续迭代成本。
- 写作体验：改进章节编辑与 AI 生成流程体验。

## 3. 承接 MVP 已完成基线（不在 V1 重复计入）
以下能力已在 MVP 后期完成，不再作为 V1 新目标重复计算：
- 测试与安全基线：
  - 集成测试显式开关（`INTEGRATION_TEST=1`）。
  - 测试库命名护栏（`MYSQL_DSN` 必须包含 `_test`）。
  - API 集成测试已覆盖 Auth/Novels/Characters/Chapters 主链路。
- 前端可维护性改造（第一轮）：
  - 大页面拆分到 hooks/components（已进行多轮）。
  - API 错误提取逻辑统一。
- 章节编辑体验（第一轮）：
  - 生成中状态提示。
  - 生成失败重试入口与提示优化。
- 运维基础：
  - MySQL 备份/恢复脚本与 README 使用说明。

## 4. V1 范围（新增）
- 测试体系补强（增量）：
  - 补齐失败路径与边界场景（权限、参数、状态冲突）。
  - 增加前端关键流程测试，先覆盖高风险写作链路。
- 工程结构重构（增量，不改业务功能）：
  - 继续拆分剩余重页面和重 hook。
  - 进一步去重同构状态与表单逻辑。
- 写作与设定体验（增量）：
  - 修仙题材等复杂设定的结构化管理（如法器/丹药/阵法等知识卡）。
  - 编辑页对“高频写作辅助信息”提供更顺手的展示/调用方式。
- 运维与发布（增量）：
  - 增加“安全迁移 + 回滚”操作手册。
  - 增加开发/测试/生产环境配置分层说明。
  - 增加 AI 生成调参指南（参数组合 + 指令模板 + 排查手册）。

## 5. V1 当前进展（已完成）
- V1-1 已完成：Lore Entries 后端最小闭环
  - 新增 `lore_entries` + `lore_entry_characters` 结构
  - 新增后端 CRUD API（含人物多对多绑定）
  - 绑定人物支持：空 / 单人 / 多人
  - 权限约束：`character_ids` 必须属于当前用户的当前小说
- V1-4（前半）已完成：Lore Entries 前端最小闭环
  - 左侧导航新增“小说设定”
  - 前端已支持设定卡列表/创建/编辑/删除
  - 设定卡表单支持人物多选绑定
- V1-4（后半）已完成：章节生成联动设定卡
  - 章节生成接口支持 `lore_entry_ids`
  - 写作页支持“本章相关设定”多选
  - 生成 prompt 可注入所选设定卡信息
- V1-5（前半）已完成：小说工作区信息架构重构
  - 左侧导航改为“小说列表直接选择”
  - 右侧改为横向 Tab 切换四个模块
  - 移除四个模块内重复“选择小说”步骤
- V1-5（后半）已完成：章节生成质量控制参数
  - 章节生成接口支持目标字数范围：`target_word_min / target_word_max`
  - 章节生成接口支持风格硬约束开关：
    - `avoid_translation_tone`
    - `avoid_modern_slang`
    - `keep_pov_consistent`
    - `keep_tense_consistent`
  - 写作页“生成指令”面板已接入对应表单项与本地草稿持久化
  - “最近章节参考数”已迁移到章节写作页生成面板（本次生成参数），不再放在小说详情编辑中
- V1-2（后端部分）已完成：失败路径测试增量补强
  - 新增 `chapters/generate` 失败场景集成测试
  - 覆盖 `generation_instruction` 缺失、非法 `character_ids`、非法 `lore_entry_ids`、跨用户越权访问
- V1-2（前端部分）已完成：章节编辑核心交互最小测试
  - 新增 `useChapterEditor` 测试
  - 覆盖生成失败提示与重试状态
  - 覆盖保存失败不触发生成重试
  - 覆盖生成请求携带 `character_ids + lore_entry_ids`

## 6. V1 非目标
- RAG / 向量数据库
- MCP / 多 Agent 编排
- Google Drive 集成
- 商业化复杂 UI 与完整运营后台

## 7. 约束与原则
- 延续 Go + Echo + React + TypeScript + MUI 技术栈。
- 优先做“小步提交 + 可回滚”的阶段改造。
- 单阶段只做一件事：需求明确、验收明确、文档同步。
- main 分支始终保持可启动、可迁移、可验证。

## 8. 验收标准（V1 总体）
- 后端：关键主链路集成测试可在测试库稳定通过。
- 前端：核心页面交互可用，错误提示一致，复杂页面进一步降复杂度。
- 文档：README、设计书、阶段总结同步更新。
