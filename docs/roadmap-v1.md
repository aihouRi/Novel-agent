# Novel Agent V1 Roadmap

更新时间：2026-05-19

## 1. 文档作用
本文件定义 V1 的阶段顺序、每阶段交付物与验收标准，用于执行跟踪与复盘。

## 2. 阶段规划

## V1-0 基线确认（已完成，承接 MVP）
- 说明：以下内容已在 MVP 末期完成，不再重复实施：
  - 后端 API 主链路集成测试（Auth/Novels/Characters/Chapters）
  - 集成测试安全护栏（`INTEGRATION_TEST` + `_test` 库名约束）
  - 前端第一轮结构拆分与错误提示统一
  - 备份/恢复脚本与文档

## V1-1 测试增量补强
- 目标：在既有基线上补齐高风险失败路径与边界场景。
- 交付物：
  - 后端 API：补齐权限失败、参数非法、状态冲突场景。
  - 前端：章节写作主链路最小测试（生成/保存/提示）。
- 验收：
  - 测试可在约束环境稳定运行。
  - 不影响开发主库数据。

## V1-2 前端结构重构增量（不改功能）
- 目标：进一步降低页面复杂度和重复逻辑。
- 交付物：
  - 剩余重页面拆分为 hooks/components。
  - 重复状态与表单逻辑继续抽象复用。
- 验收：
  - 关键页面行为不变。
  - `npm run build` 通过。

## V1-3 世界观知识卡（新功能）
- 目标：支持修仙等题材中的“法器/丹药/阵法”等复杂设定管理。
- 交付物：
  - 新增基础实体（建议先统一为“设定卡”模型）。
  - 提供最小 CRUD 与与 novel 关联。
  - 生成章节时可选择性注入设定卡上下文。
- 验收：
  - 能创建、编辑、查询、删除设定卡。
  - 生成接口能按选择带入设定信息。

## V1-4 章节编辑体验优化（增量）
- 目标：提升长文写作效率与可控性。
- 交付物：
  - 结合设定卡信息优化编辑侧栏与提示区。
  - 关键交互细节继续优化（按钮、面板、异常提示）。
- 验收：
  - 常见操作路径无明显阻塞。
  - 用户可直观看到当前状态与下一步动作。

## V1-5 稳定性与运维文档（增量）
- 目标：降低误操作和环境问题。
- 交付物：
  - 增加迁移回滚手册与风险清单。
  - README 的环境分层说明补齐（dev/test/prod）。
- 验收：
  - 新环境可按文档完成启动。
  - 高风险操作前后流程清晰。

## 3. 执行规则
- 每个子阶段独立分支。
- 每个子阶段单独提交并更新 `docs/.local-progress.md`。
- 若阶段目标变化，先更新本 Roadmap 再开发。
