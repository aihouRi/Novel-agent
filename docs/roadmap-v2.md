# Novel Agent V2 Roadmap

更新时间：2026-05-23

## 1. 文档作用
本文件定义 V2 的阶段顺序、每阶段交付物与验收标准，用于执行跟踪与复盘。

## 2. 阶段规划

## V2-0 基线确认（待开始）
- 目标：冻结 V1 可用基线，明确 V2 改动边界。
- 交付物：
  - V1 能力清单与回归检查清单。
  - V2 阶段拆分与优先级确认。
- 验收：
  - V2 立项范围清晰且可分阶段实施。

## V2-1 RAG 最小闭环（待开始）
- 目标：让 AI 生成使用可检索上下文，降低剧情与设定跑偏。
- 交付物：
  - 可索引的数据源（章节/角色/设定）。
  - 召回接口与最小策略（按任务召回 Top-K）。
  - 写作页可见的“本次引用上下文”预览。
- 验收：
  - 生成链路可稳定携带召回上下文。
  - 用户可感知本次参考来源。

## V2-2 生成工作流升级（待开始）
- 目标：从一次性生成升级为多步可控流程。
- 交付物：
  - “计划 -> 生成 -> 自检 -> 改写”最小工作流。
  - 一致性检查（设定冲突、时间线、人物状态）第一版。
- 验收：
  - 生成后可自动给出风险提示与可选修正。

## V2-3 发布可用性增强（待开始）
- 目标：提升长期写作稳定性与数据安全。
- 交付物：
  - 备份/恢复流程增强与可视化操作提示。
  - 导出增强（模板化与可选结构化导出）。
- 验收：
  - 常见高风险操作有明确保护与恢复路径。

## V2-4 定稿后自动抽取入库（待开始）
- 目标：把“章节中的确定信息”沉淀到结构化数据库，减少手工整理成本。
- 交付物：
  - 抽取触发条件：仅 `final` 状态章节可触发自动抽取。
  - 抽取来源：优先使用“章节总结 + 正文片段”进行实体识别（人物/物品/设定）。
  - 入库策略：
    - 仅写入确定事实字段（如名称、别名、首次出现章节、描述片段等）。
    - 禁止自动写入策略字段（如 `importance_level`），此类字段保持人工维护。
  - 安全机制：
    - 抽取结果先预览，再确认入库（支持跳过/撤销）。
    - 记录抽取来源章节与时间戳，便于追溯。
- 验收：
  - 定稿章节可稳定抽取并写入候选数据。
  - 抽取误差不会直接污染核心策略字段。
  - 用户可对抽取结果进行人工确认与纠正。

## 3. 执行规则
- 每个子阶段独立分支。
- 每个子阶段单独提交并更新 `docs/.local-progress.md`。
- 若阶段目标变化，先更新本 Roadmap 再开发。
- 迭代期间持续修复新发现 bug，并同步记录。
- 迭代期间允许持续进行代码/性能优化与数据库优化（需保持可回滚）。
